# `unsafe` Inventory — C-ABI crate (`libjpeg-turbo-rs-capi`)

> **Gated.** `tests/unsafe_inventory_gate.rs` lexes every `.rs` under
> `crates/libjpeg-turbo-rs-capi/src/`, attributes each code `unsafe` token to
> its enclosing item, and fails unless this file lists exactly those items
> with exactly those counts and every cell filled. Adding, removing or moving
> an `unsafe` therefore fails CI until the row here changes — the inventory
> edit is part of the pull-request diff, and `.github/CODEOWNERS` routes that
> diff to the maintainer. **Edit this file, never the gate, when a count
> moves.**

**Why an inventory and not a count** (P4-141 criterion 4, GitHub
[#480](https://github.com/developer0hye/libjpeg-turbo-rs/issues/480)). A raw
count says nothing about risk, and nowhere less than here: this crate is
`extern "C"` end to end, so *every* entry point is an `unsafe fn` by
construction and the declaration sites alone would inflate any total. What
matters per site is *why* safe Rust cannot express it, *which invariant*
makes it sound, *whether a safe caller can reach it*, *which test* would
catch the invariant breaking, *which tools* execute it, and *who last read
it*. That is the row. The companion document for the root crate is
[`UNSAFE_INVENTORY.md`](UNSAFE_INVENTORY.md).

## Scope and units

- **Scope:** every `.rs` under `crates/libjpeg-turbo-rs-capi/src/` — the
  TurboJPEG 3 surface, its TurboJPEG 1.x/2.x legacy aliases, the libc
  allocation helpers, the `jpeg_memory_mgr` port, the mozjpeg-compat stubs and
  the classic `jpeg_*` surface in `jpeglib.rs`. **Nothing is deferred:** the
  gate's `DEFERRED` list is empty and `deferrals_are_live_and_named` keeps it
  that way, so a file added to this tree with `unsafe` in it fails CI until it
  has a section here. With `jpeglib.rs` landed on 2026-09-09 the crate is
  complete, and with it P4-141 criterion 4 — the root crate's companion is
  [`UNSAFE_INVENTORY.md`](UNSAFE_INVENTORY.md).
- **Site:** one code `unsafe` token — outside comments, strings and
  literals — as found by the lexer in `tests/helpers/unsafe_scan.rs`. Under
  the crate's `#![deny(unsafe_op_in_unsafe_fn)]`, an `unsafe fn` and the
  `unsafe { … }` block inside it are **two** sites; that is deliberate, so
  the declaration (the contract) and the operation (the risk) are counted
  apart. For an `extern "C"` entry point the declaration site is the more
  interesting of the two: it is where the C caller's obligation is written
  down, and nothing in the body can check it.
- **Item:** the row key — the enclosing `fn` (the nearest declaration at or
  above the site), or the header for `unsafe impl` / `unsafe trait`. A site
  at module level, including one inside a `type` alias or a `static`
  initialiser, keys `(module)`. Attribution reads a comment-masked copy of
  the source, so neither a commented-out `fn` nor the phrase `unsafe impl …`
  in a trailing comment can name a row. It is a deterministic attribution,
  not a parser: the gate's failure message prints the exact rows it expects.
- **Sections** are one per file, `## \`path\` — N sites`, in path order; rows
  within a section are in first-occurrence order. Sites inside `#[cfg(test)]`
  code are inventoried too and say **test-only** in *Safe caller* — a test
  that dereferences a raw pointer is still code ASan needs to see.
- **The `---` rule below is the boundary.** Everything above it is this
  preamble, which explains the format with its own `##` headings and its own
  table and carries no inventory data. Everything below it is read by the
  gate, where a `## ` heading that is not `## \`path\` — N sites` is an error
  rather than prose.

## Columns

| Column | What goes in it |
|---|---|
| Item | The enclosing item, in backticks. Machine-checked. |
| Sites | Code `unsafe` tokens attributed to the item. Machine-checked. |
| Why not safe Rust | The concrete reason: an `extern "C"` declaration whose caller is C, a raw pointer plus a length the caller asserts, `Box::from_raw` reclaiming a handle, a `#[repr(C)]` vtable of `unsafe extern "C" fn`. |
| Invariant | What must hold — bounds, lifetime, aliasing, allocator provenance — and **where it is established**: which argument check, which `ImageLayout`/`checked_span` call, or "the caller's contract, unchecked" when nothing in the process can verify it. |
| Safe caller | `no: C ABI` for an exported entry point whose obligations belong to the C caller; `yes: via …` when 100 % safe Rust in this workspace can reach it; `test-only`. |
| Regression test | The test(s) that would fail if the invariant broke, by function name and file. `**none** — …` is an honest answer and a gap to file. |
| Tool coverage | Which CI legs execute the site (vocabulary below), and — just as important — which do not. |
| Reviewer | Who last read the code against the row, and when. |

**What the gate enforces, and what it does not.** It enforces that every site
is *listed*, that each row's count is exact, and that no cell is empty or a
template — so an added, removed or moved `unsafe` cannot merge without an
inventory edit in the same diff. It cannot check that a justification is
*true*. Content is a review question, which is what `.github/CODEOWNERS` is
for.

**A note this crate needs and the root crate does not.** *Safe caller* reads
`no: C ABI` on nearly every row, and that is a statement about Rust's
`unsafe` keyword, not about reachability: these symbols are exported from a
cdylib and any C program in the world can call them with any pointer it
likes. The obligation is real, it is simply not one the compiler can place on
anybody. What the `unsafe fn` marking buys is that a *Rust* consumer of this
crate's `rlib` cannot reach them without acknowledging it — the point P4-137
made when it removed a safe wrapper that implied otherwise.

## Tool-coverage vocabulary

The legs, as configured on 2026-09-08 (`.github/workflows/`). Note how few of
them reach this crate: `cross-arch.yml` runs `cargo test --tests` and
`wasm.yml` runs `cargo test --target wasm32-wasip1`, both of which select the
*root* package only, and `full-c-parity.yml` names root `--test` targets.
`armv7.yml` is the one architecture leg that names this crate, and it names
three things.

- **Integration Tests** — `ci.yml` *Integration Tests* (ubuntu x86_64) and
  its *(oracle 3.2.0)* twin. The step `Complete C-ABI integration inventory
  (P4-175)` runs `cargo test -p libjpeg-turbo-rs-capi --tests --features png
  --no-fail-fast`, i.e. **every** C-ABI integration suite, including files
  added since; the named focused steps around it are earlier signals on the
  same suites. This is the primary leg for everything in this document.
- **C-ABI unit tests** — the same job's `cargo test -p libjpeg-turbo-rs-capi
  --lib`: the `#[cfg(test)]` modules *inside* these sources, on the stable
  toolchain, uninstrumented.
- **ASan / UBSan** — `sanitizers.yml`: `cargo +nightly test --workspace
  --lib` with `-Z sanitizer=address` / `-Z ub-checks=yes`. `--lib`, so it
  covers this crate's own unit tests and **no integration suite**.
- **C-boundary ASan** — `sanitizers.yml`'s third job: a C harness compiled
  with `-fsanitize=address,undefined` `dlopen`s the ASan-instrumented cdylib
  and drives `tj3Init → tj3DecompressHeader → tj3Decompress8 → tj3Destroy`
  (plus `tj3Get`) over three fixtures — baseline, progressive and
  arithmetic. The only leg where a real C caller crosses this boundary, and
  it reaches five entry points. It allocates its own buffers with `malloc` /
  `free`, so the shared-allocator contract `tj3Alloc` / `tj3Free` exist for
  is **not** exercised here.
- **Miri** — `ci.yml`: `cargo miri test -p libjpeg-turbo-rs-capi --test
  capi_create_abi_guards --test capi_thread_affinity`. Two suites, both on
  the classic `jpeg_*` surface, so they reach `jpeglib.rs` and nothing else:
  **no TurboJPEG entry point in this document runs under Miri**, and no row
  outside the `jpeglib.rs` section may claim it.
- **ARMv7 (32-bit, qemu)** — `armv7.yml`: `-p libjpeg-turbo-rs-capi --lib`
  plus `capi_layout_adoption` and `capi_span_overflow_guards`, under
  `-C overflow-checks=on`. The leg where a 32-bit `usize` wrap in a span
  becomes a loud failure.
- **Windows / CAPI ABI Checks** — `ci.yml` builds every workspace test target
  (`--no-run`) on Windows and runs `format_message` there; *CAPI ABI Checks*
  (ubuntu, macos, windows) runs `abi_offsets` and `symbol_inventory` in
  release.
- **Stock-tool link** — `tests/capi_stock_tool_link.rs` in the **root** crate
  (`stock_tools_link_against_our_shim`) builds upstream `djpeg`/`cjpeg`/
  `jpegtran` against the shim and diffs their output against the system
  binaries, so it drives the memory manager the way libjpeg itself does. It
  runs wherever the root crate's `cargo test --tests` runs — Integration
  Tests, C Interop (macos aarch64) and the `cross-arch.yml` legs — and skips
  without a C compiler or the stock tools.
- **Not covered anywhere:** `cross-arch.yml` and `wasm.yml` (root package
  only), `full-c-parity.yml` (root `--test` targets), and Fuzz Smoke — all
  twelve fuzz targets drive the Rust API, so **no fuzzer reaches the C ABI**.
  That is criterion 3 of P4-141, still open.

## Maintaining a row

1. Run `cargo test --test unsafe_inventory_gate`. The failure names the file,
   the item and the count it found, with the source lines, and prints a
   paste-ready section for a file that is new here.
2. Re-read the code, not just the diff: a changed count means the contract
   may have changed. Update every cell the change touches, and the
   *Reviewer* cell always.
3. If the honest *Regression test* cell is `**none**`, add it to
   [P4-191](https://github.com/developer0hye/libjpeg-turbo-rs/issues/609) —
   the item that collects them — before the pull request merges, rather than
   opening a sibling.
