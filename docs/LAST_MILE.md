# Last Mile Replacement Gate — Index

> **Purpose:** the release gate for "can `libjpeg-turbo-rs` replace C libjpeg-turbo as a system library?" — Rust-native APIs, TurboJPEG/TJ3 C ABI, classic `jpeg_*`, stock tools, downstream wrappers.

> **For agentic workers:** read this index first. Open the phase file(s) below ONLY for the items you are working on. Do not load all phases by default.

**Tech stack:** Rust 2021, `libjpeg-turbo-rs`, `libjpeg-turbo-rs-capi`, upstream sources in `references/libjpeg-turbo`, Homebrew/system `djpeg`/`cjpeg`/`jpegtran`, Pillow/ImageMagick smoke harnesses.

## Current Status (2026-08-08)

Project replacement readiness is tiered (this list is the canonical T1–T4 framing; [README.md](../README.md#c-abi-replacement-tiers) points here):

- **T1.** Rust crate (`use libjpeg_turbo_rs::*;`) — **feature-ready, but the safe API is not yet sound.** Functionality, C cross-validation and performance are mature. The 2026-08-09 soundness audit's headline defect — safe Rust reaching an AVX2 `target_feature` kernel with unvalidated slices ([P4-135](last_mile/phase4.md#p4-135-public-safe-simd-wrappers-let-safe-rust-reach-target_feature-kernels-with-unvalidated-slices--partial-external-safe-to-ub-path-closed-in-crate-unsafe-fn-sweep-pending)) — was closed 2026-08-10, both by path and by dispatch table. A 2026-08-10 re-audit found the audit's other memory-safety defects also fixed: the uninitialized `Vec` (P4-136), the forged handle lifetime (P4-137) and the `BitWriter` double free (P4-138) are all closed, the last confirmed under both Miri and ASan. **No known live UB remains in the safe Rust API.** Treat T1 as ready for *use* rather than as a memory-safety *guarantee* nonetheless, for two reasons that are about evidence, not a known hole: P4-139's layout arithmetic is still *decentralised* — every span is now checked and the rule is enforced by a gate, but the checking is written out per site rather than owned by one type — and P4-141 records that none of these findings came from a gate, P4-135 having been found by reading code and P4-143 by review. A guarantee needs the verification program, not just the absence of a current report. See also [P4-140](last_mile/phase4.md#p4-140-public-documentation-claims-safety-and-drop-in-status-the-code-does-not-support--closed-2026-08-09) for the wording this changes.
- **T2.** TurboJPEG cdylib (`libturbojpeg.so.0`) — **ready** for TJ3 consumers (opaque-handle API, no struct ABI risk). Legacy 1.x/2.x surface is partial: **21 legacy aliases wired** in `crates/libjpeg-turbo-rs-capi/src/legacy.rs` (lifecycle `tjInitCompress`/`tjInitDecompress`/`tjInitTransform`/`tjDestroy` + `tjCompress2`/`tjDecompress2`/`tjDecompressHeader3` + `tjTransform`/`tjEncodeYUV3`/`tjDecodeYUV` + buffer-size helpers + `tjLoadImage`/`tjSaveImage` + `tjGetErrorStr2`); **18 deliberately deprecated** (v1 / un-versioned variants like `tjAlloc`, `tjFree`, `tjCompress`, `tjGetScalingFactors`). P4-18 closed 2026-05-19 via Option B — `docs/ABI_COMPATIBILITY.md` carries a per-symbol migration matrix and a tiny-shim recipe (`unsigned char *tjAlloc(int b) { return tj3Alloc((size_t)b); }` pattern) so consumers compiled against the missing 18 can either recompile against TJ3 or ship a one-translation-unit shim. Option A (wiring the 18 in our cdylib) remains tracked in P4-18's body for the case where a downstream consumer cannot ship the shim translation unit.
- **T3.** Classic libjpeg v8 cdylib (`libjpeg.so.8`) — **experimental/partial, not yet a general drop-in.** The shim defaults to the v8 SONAME, and the pinned OpenCV 4.6 workload proves real binding, encode/decode, and bidirectional interoperability for that measured default path. It does not cover the open P0/P1 ABI, state, option, and error gaps P4-84..P4-115 (the P0 destination-ownership gap P4-108 and the create-guard P0 P4-110 are both closed; the test-integrity gap P4-116 closed 2026-08-08); P4-81 separately tracks ELF symbol versions. Two further T3 blockers are structural rather than behavioural: the shipped library's export surface is a `jpeg_*` glob that also stamps 16 test-only accessors as reference v8 API (**P4-129**), and our per-`cinfo` threading contract is stricter than the library we replace (**P4-132**) — stricter than upstream 3.2, which removed TLS from its libjpeg API entirely. The harness is also not yet run against the artifact we ship (**P4-124**). Treat it as downstream evidence, not blanket compatibility.
- **T4.** System v6b/v7 drop-in (`libjpeg.so.62` / `libjpeg.so.7`) — **explicit non-goal** until per-ABI cdylib matrix ships. v6b is available only behind explicit `CAPI_SONAME=libjpeg.so.62 + CAPI_ACK_V6B_SONAME=1` opt-in.

Phase 3 history: P3-1 / P3-2 / P3-3 / P3-4 / P3-5 / P3-6 all CLOSED. P3-2 closed 2026-05-09 with the full 12-bit `jpeg_*_raw_data` backend wired through `libjpeg_turbo_rs::raw_data_12::{compress,decompress}_raw_12`. Phase 4 post-gate corrections: P4-1 exported `jpeg_calc_jpeg_dimensions` (closed 2026-05-10); P4-2 introduced the T1–T4 replacement-tier framing (closed 2026-05-17); P4-3 flipped the default C-ABI SONAME from `libjpeg.so.62` to `libjpeg.so.8` (closed 2026-05-17).

## Replacement Gate (8-item checklist)

Do not call the project a libjpeg-turbo C replacement until all are true:

1. `cargo test --workspace --no-fail-fast` is green with no product-path ignored tests except explicitly slow release-only stress tests.
2. `cargo test --test capi_stock_tool_link -- --include-ignored` is green, or the ignored attributes are removed and the default run is green.
3. `cargo test --test capi_pillow_compat -- --nocapture` fails on blocker code 3 until fixed, then passes through real Pillow decode+encode.
4. `cargo test -p libjpeg-turbo-rs-capi --test tjunittest_link -- --include-ignored --exact tjunittest_default_suite_passes` is unignored and green in the normal suite.
5. Stock `djpeg`, `cjpeg`, `jpegtran` and real C harnesses cross-validate output plus public state/ownership/error contracts, with no open P0/P1 classic-ABI or test-integrity gaps.
6. The shim exports every symbol required by the linked stock tools and by the Pillow/ImageMagick smoke harnesses, including high-precision raw-data entry points.
7. Performance reporting is re-run after correctness is green. Correctness blockers take priority over decode/encode microbenchmarks.
8. On GNU/Linux, the candidate exports the reference-compatible ELF symbol-version nodes required by prebuilt consumers, and replacement runs produce no `no version information available` loader warnings.

Items 5, 6 and 8 are not green, and the checklist has a **precondition it does not currently state**: the safe Rust API must be sound. P4-135 showed it was not, which no item below tests for — the gate was written around C-ABI parity and assumed Rust-side soundness. As of the 2026-08-10 re-audit no known live UB remains (P4-135/136/137/138 all fixed), but the precondition is still unmet as *evidence*: P4-139's decentralised layout arithmetic and P4-141's verification program must close before any replacement claim, independently of items 1-8. Note that every one of these findings came from reading code or review, never from a gate — which is precisely P4-141's point. P4-84..P4-115 track the classic contract gaps; P4-81 tracks ELF versions, and its downstream re-verification is blocked on P4-124 (the harness tests the cargo cdylib, not the staged library). Item 6 is two-sided: **P4-129** shows the shipped surface exports 16 symbols it should not, so "exports every required symbol" is necessary but not sufficient. The test-integrity gap P4-116 closed 2026-08-08. T3 is proven only for the measured workloads.
